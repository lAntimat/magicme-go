# Сборщик статистики go.magicmebook.ru

Cloudflare Worker записывает в D1 число событий по минутам UTC. В отдельной таблице хранится первая наблюдавшаяся минута каждого источника. По ней отчёт определяет, с какого момента есть данные. Отсутствие событий после начала сбора соответствует нулю за покрытый интервал. Пропуски при сбоях доставки по одним агрегатам определить нельзя.

Сборщик сохраняет минуту UTC, название события и счётчик. Код не сохраняет IP, User-Agent, referrer, URL, cookie, ключи или отдельные события. Логи и трассировки Worker выключены в `wrangler.toml`. При настройке Cloudflare проверьте, что для адреса сборщика также не включён отдельный экспорт журналов запросов. Раз в сутки сборщик удаляет агрегаты старше 92 суток UTC. Этот срок покрывает 90 местных календарных дней с запасом на сдвиг границ при переводе в UTC. Первая минута наблюдения остаётся в таблице покрытия. Временные резервные копии D1 подчиняются сроку хранения Cloudflare Time Travel. [Cloudflare Time Travel](https://developers.cloudflare.com/d1/reference/time-travel/).

## События

`POST /v1/events` принимает `text/plain`, один ключ в теле запроса без пробелов и перевода строки и заголовок `Origin`. URL не содержит параметров. Ответ при записи — `204`.

| Ключ | Кто отправляет и когда |
| --- | --- |
| `go_open` | `GO_ORIGIN` при открытии страницы-переходника |
| `go_click_open` | `GO_ORIGIN` при нажатии «Открыть в браузере» или «Перейти на сайт» |
| `go_click_copy` | `GO_ORIGIN` при нажатии «Скопировать ссылку на сайт» |
| `site_open` | `SITE_ORIGIN` при загрузке основного сайта с меткой перехода `go` |

Переходник отправляет события без ожидания ответа, с `keepalive`, без cookie и referrer. Автоматический переход даёт только открытие `go`. При недоступном буфере обмена нажатие копирования учитывается как нажатие. Заголовок `Origin` ограничивает браузерные запросы. Клиент вне браузера может его подставить, поэтому счётчики пригодны для оценки трафика, а события могут теряться при сетевых сбоях.

## Отчёт

`POST /v1/report` принимает `Authorization: Bearer <REPORT_TOKEN>` и JSON вида `{"windows":[{"start":29928975,"end":29928990,"group":0}]}`. URL без параметров. Максимальный размер тела — 155 КиБ.

- `start` и `end` — целые числа, минуты с начала Unix-эпохи в UTC. В интервал входит `start`, граница `end` исключена.
- До 2300 непустых интервалов отсортированы по времени и не пересекаются. Допустимы промежутки между интервалами. `group` — целое число от 0 до 89. Несколько интервалов могут относиться к одной группе.
- Начало интервала может быть не старше 91 суток относительно текущей минуты UTC. Конец может быть до 26 часов вперёд, чтобы передать границу текущего местного дня. Счётчики включают события по текущую минуту UTC включительно.

Приложение формирует интервалы по выбранному часовому поясу. Сборщик суммирует значения по `group` и `event`. Ответ содержит `coverage.go` и `coverage.site` с первой минутой UTC либо `null`. В `rows` возвращаются только положительные суммы в формате `{ "group": 0, "event": "go_open", "count": 1 }`.

## Локальная проверка

Из корня репозитория выполните `node --test` с Node.js 22.17 или новее. Тесты используют реальные SQL-запросы в SQLite. Для проверки в среде Workers можно поднять локальный Worker из папки `collector`.

```sh
go_stats_state=$(mktemp -d "${TMPDIR:-/tmp}/magicme-go-d1.XXXXXX")
npx --yes wrangler@4.169.0 d1 migrations apply DB --local --persist-to "$go_stats_state"
npx --yes wrangler@4.169.0 dev --local --local-protocol https --test-scheduled --persist-to "$go_stats_state" --var REPORT_TOKEN:local-test --var GO_ORIGIN:http://127.0.0.1:8000 --var SITE_ORIGIN:http://127.0.0.1:8001
```

Для проверки из браузера задайте `https://localhost:8787` в метатеге `go-statistics-base` во временной копии страницы, запустите её на `http://127.0.0.1:8000` и разрешите локальный сертификат Wrangler в тестовом браузере. `Origin` страницы должен совпадать с `GO_ORIGIN`, включая протокол, хост и порт.

## Подготовка к выпуску после согласования

1. Получить доступ к Cloudflare-аккаунту с правами на управление Workers и D1 и выбрать HTTPS-адрес для сборщика. Подойдёт адрес Worker на `workers.dev` с включённым поддоменом аккаунта. Для собственного имени настройте отдельный Custom Domain.
2. Для stage и production использовать отдельные Workers, базы D1 и ключи. В рабочей конфигурации заменить нулевой `database_id` на ID окружения и при необходимости заменить `database_name`, `GO_ORIGIN`, `SITE_ORIGIN`. Применить миграцию командой `wrangler d1 migrations apply DB --remote` для выбранной базы. [Документация D1](https://developers.cloudflare.com/d1/get-started/).
3. Создать случайный `REPORT_TOKEN` и передать его в секрет Worker и серверный секрет приложения. Поддерживаемый способ первой публикации — `wrangler deploy --secrets-file <путь>` с защищённым файлом вне Git. [Документация Worker Secrets](https://developers.cloudflare.com/workers/configuration/secrets/).
4. Использовать один и тот же адрес Worker в серверной конфигурации основного сайта и в `go-statistics-base` страницы-переходника. В метатеге указывать HTTPS origin без пути, query и фрагмента. Проверить на stage записи всех четырёх событий и доступ к отчёту только по ключу перед согласованием активации production.
